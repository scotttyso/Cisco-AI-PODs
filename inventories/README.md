# Site inventories

`inventories/example/` is a non-deployable sample showing the expected
Ansible inventory layout. It uses documentation-only addresses, placeholder
Intersight tenant names, example hostnames, and `CHANGE_ME` vault values.
Never use it as a real site inventory.

Site inventories are generated by the UI for each environment and belong in a
separate environment directory. Use the generated inventory explicitly with
Ansible (`-i inventories/<environment>/inventory.yml`) and pass its directory
when invoking inventory-aware scripts. Automation must not select a site
inventory implicitly. The generated inventory keeps the same contract as the
example: `inventory.yml`, `group_vars/`, and `host_vars/`.

Shared Intersight values (`intersight_*`) and site-wide DNS, search domains,
NTP, domain, and timezone values (`aipod.*`) live in `group_vars/all.yml`.
ND-specific settings live in `group_vars/nd_cluster.yml`; backend fabric
records and features live in `group_vars/backend_fabric_switches.yml`.
Secrets belong only in the environment's gitignored `group_vars/vault.yml`,
created from `group_vars/vault.yml.example`. Keep credentials out of tracked
files, command arguments, chat, and logs. Encrypt the vault where appropriate
and restrict its permissions.

For stage 02, fabric keys are the `key` values in `be_fabrics`; matching
switches belong to the parent `backend_fabric_switches` group and each child
`backend_fabric_<key>` group. Switch identity, role, management address, and
credential reference are provided by `host_vars`. See the stage 02 README for
the cabling-plan and playbook contract.
